## 可配置 Agent 上报间隔（2026-11-02）

- 节点设置新增“Agent 上报设置”，可选 1 / 3 / 5 / 10 / 15 秒，默认 5 秒。通过现有扩展配置版本与 `reporting:1` 能力协商下发，写入成功后切换调度；失败继续使用原间隔，旧 Agent 显示需升级。
- 复用现有配置存储，无数据库版本变更；保留探测、诊断与工作负载设置。网络与资源采样仍分别为 1 秒和 5 秒，浏览器 SSE 仍每 5 秒推送。
- 陈旧 / 离线状态按上报间隔的 3 / 9 倍计算，至少 15 / 45 秒；配置待确认时按最长间隔容错。资源告警连续性、流量预测和探测页面同步使用相应新鲜度，自定义告警触发阈值保持原值。
- 本地验证完成：完整 API **85 项通过**；Go 完整竞态测试与 vet、类型检查、生产构建通过。浏览器分批完成 **18 项定向验收**，包含五档选项、实际 15 秒上报/确认/刷新持久化、手机键盘与未保存值保留、旧 Agent 提示，以及原总览/诊断回归。截图：[桌面](../artifacts/reporting-desktop.png) / [手机](../artifacts/reporting-mobile.png)。Ant Design lint 无错误；固定 5 个选项完整渲染以供无障碍访问，产生 1 条大数据集虚拟滚动的通用性能提醒。

## 上报 HTTP 500 修复（2026-11-02）

- 根因：早期 v4/v5 数据库的 `probe_states` 只有 7 列；代码新增 `first_failure_at` 时只改了建表语句，缺少既有数据库的增量迁移。探测结果触发告警状态写入时，整批上报回滚并返回 500。
- 修复：增加事务化 v6 迁移，缺列时补齐，已存在该字段时保留原值；旧失败计数、成功计数、活动事件和历史均保留。旧状态无法还原首次失败时间，保守采用最后一次已知失败时间。状态写入显式列名，Agent 无需重编译或清空同步进度。
- 新增 4 项回归：旧 v5 经 HTTP 接口拒绝后升级、原批次重传与去重、连续失败/恢复；v4/v5 旧表升级；已有字段重复迁移；失败回滚与重试。验证结果见 [验收记录](verification.md)。
- 当前开发环境使用 `tsx watch`，保存源码后自动重载；只读复查工作区数据库已从 v5 / 7 列变为 v6 / 8 列并收到新上报。未手动重启服务、提交、推送或发布镜像；其他部署需更新中心程序并启动迁移。
