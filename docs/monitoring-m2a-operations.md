# M2-A 网络探测：使用与升级

本地实现日期：2026-11-02。尚未发布或部署。页面设计见 [草图与交互](monitoring-m2a-design.md)，实际验收见 [验证记录](verification.md)。M1 告警、通知密钥和流量套餐继续按 [M1 指南](monitoring-m1-operations.md) 管理。

## 升级顺序

先备份中心，再升级中心；中心数据库 v3→v4。确认现有 Agent 上报、累计流量、历史和登录正常后，再选择一台 Agent 试升级到源码默认版本 1.2.0。Agent 数据库 v2→v3，保留 source_id、原流量/资源/磁盘数据和游标。没有探测需求的 Agent 无需立即升级。

备份运行中 SQLite 使用一致性备份 API，或停止对应服务后完整保存数据目录；分别保留中心镜像、Agent 二进制、配置、数据库及 M1 通知密钥。旧程序会拒绝新库，回退必须恢复匹配的程序、配置和数据库，不能只替换可执行文件。

新 Agent 首次与断线重连先发基础 v1 报告，再根据 `server_capabilities.probes=1` 开启扩展。基础配置和扩展配置分别确认；页面分别显示待升级、待应用、已应用或保存失败。旧中心未返回能力时，暂停远程探测；网络中断时继续使用上次已确认支持的配置采样，待连接恢复后补传。拒绝扩展的 400/422 响应只触发一次基础协商；401/403/409 不被吞掉。

## 创建探测

进入“网络探测”，或节点详情的“网络质量”。填写名称、执行节点、协议、地址族、目标、周期与超时；默认未启用。每节点最多 10 项、并发 2，默认每 60 秒执行一次、超时 3 秒，间隔最少 15 秒。HTTP 为 GET，只接受 2xx 成功，不跟随重定向，最多读取 64 KiB 正文且不保存内容。不支持 URL 凭据、查询参数、片段、自定义头和请求体。

TCP 填写主机名/IP 与独立端口；HTTP(S) 的端口写在 URL；ICMP 不使用端口。来源节点不同，统计和告警各自独立。新建或修改后等待扩展配置应用和下一个计划时刻，错过的时刻不补发请求。

私网、环回地址默认阻止。需要探测内网时，在停止 Agent 后，向现有 `agent.json` 增加本机允许网段，例如：

```json
{
  "probe_allow_cidrs": ["10.20.0.0/16", "fd12:3456::/48"]
}
```

这是应合并到现有配置的字段示例，不是完整配置。保留原有凭据、中心地址、统计配置及文件 `0600` 权限，再重启对应服务。云元数据、链路本地、多播、未指定地址与特定地址转换网段始终禁止，不被允许网段覆盖。DNS 校验后连接固定的已核验 IP，HTTP 保留原主机名和 TLS 验证，不使用环境代理。

ICMP 使用 Linux 非特权 datagram ping socket，取决于目标内核与 `net.ipv4.ping_group_range` 等本地设置；权限不足显示“不支持 / 权限不足”，不记为丢包。先以实际 `trafficagent` 用户验证目标环境，不把整个 Agent 改为 root。实现依据为 [Go ICMP 非特权接口说明](https://pkg.go.dev/golang.org/x/net/icmp#ListenPacket)；本项目使用标准库与 Linux ping socket，无额外 ICMP 程序依赖。

## 读懂历史与告警

- 观测可用率 = 成功次数 / 有效执行次数；覆盖率 = 有效执行次数 / 分配期间应执行次数。窗口末尾尚在超时等待内的计划时刻暂不计缺口。权限不足、目标被本地策略阻止、队列跳过不计目标失败；离线和漏采会降低覆盖率。
- TCP/HTTP 统计“探测失败率”，ICMP 统计“丢包率”。每次有效探测发送一次；窗口分母、失败类别、任务版本和原始结果均可查看。成功耗时包含 DNS 和相应连接/响应过程，不等同于纯链路 RTT；P50/P95 用窗口内实际成功样本计算。
- 图表不连接缺口，版本切换分段。窗口最多 7 天，结果每页 100 条。任务可绑定多个节点，页面最多同时显示 4 个来源的历史；筛选节点可查看其余来源。停用和归档保留历史，使用“已归档任务”筛选查看。
- 连续 3 次有效失败触发，连续 2 次成功恢复；跨超过 1.5 个周期的缺口重新计数。未知观测不会解除已有异常。迟到的旧版本结果只入历史，不更新当前状态；超过 3 个周期的新鲜度窗口不会触发新的异常。
- HTTPS 证书在 14/7/3 天去重提醒，初次已跨多档时只发最高档摘要。连接或 TLS 错误会单独显示；没有读取到证书时到期时间保持未知，不填 0。证书更换后关闭旧证据并按新到期时间重新判定。
- 通知复用已有渠道、持久队列、维护和有限静默；留空渠道仍记录事件。告警详情可跳转相应探测历史。任务改动、停用、归档和节点停用会配置关闭原事件并取消未完成通知。

## 保留与重新同步

探测原始结果两端保留 7 天，原流量长期保存策略不变。Agent 删除过期未确认结果时持久记录丢弃数量与最早/最晚时刻，页面明确显示缺口。中心每小时清理探测明细；证书档位去重与活跃事件分别保留。

探测有独立 revision、分页及 ACK。缺少探测 ACK 不推进该流；基础报告仍能确认自己的流。每个流每次最多 256 条，总报告预算 1.5 MiB，按流轮流分配并保留各流最旧待传记录，低于中心/Nginx 的 2 MiB 限制。

`scripts/agent-resync.py` 现兼容完整 v2/v3 Agent 数据库，默认只读预览；v3 会为指定时间范围的探测记录分配新 revision，同时更新 JSON 记录中的 revision，保留 sample_id/source_id。应用前必须停止 Agent、提供独立备份路径；原有停止确认及高水位保护仍有效。示例命令见 [M1 指南](monitoring-m1-operations.md)。

中心恢复较旧备份后，先核对任务与分配版本仍存在。备份之后新建的任务配置无法从仅含结果的历史重建，不能对这些结果宣称自动恢复；未知分配返回明确错误并保留待传批次。扩展配置确认领先于中心时返回 409；停止 Agent、备份配置后将 `applied_extensions_config_version` 设为 0，核对中心分配，再恢复协商。不要修改凭据或 source_id，也不要未经核实恢复更旧的 Agent 计数器库。

## 验证边界

本地测试覆盖独立配置、旧协议兼容、地址限制、DNS 固定、成功/超时/HTTP/TLS 分类、IPv6 TCP、ICMP 成功及注入权限失败、事务迁移、去重、告警、字节预算、保留与重新同步。浏览器联调使用同一主机上的两个独立 Go Agent 和隔离 HTTP 目标。生产数据库迁移、实际 VPS、systemd/OpenRC 常驻运行、真实公网 HTTPS 目标及 arm64 设备运行仍须在发布前验证；交叉编译通过不代表设备验收。
