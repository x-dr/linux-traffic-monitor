# 系统诊断与运行管理指南

日期：2026-11-02。设计：[说明](monitoring-m2b-m3-design.md) / [布局](monitoring-m2b-m3-layout.svg)。

## 升级及默认状态

中心数据库 v6，Agent 数据库 v4，Agent 默认源码版本 1.3.0。中心先升级；旧 Agent 1.1/1.2 保持原监控与探测。新 Agent 首次仅发送基础字段，确认中心的 diagnostics:1 / workloads:1 后才发送新流。旧中心 400/422 触发一次基础请求重协商；不确认被拒批次、不丢弃本地记录。

若中心日志出现 `table probe_states has 7 columns but 8 values were supplied`，说明旧库缺少探测状态的 `first_failure_at` 字段。按 [部署指南](deployment.md) 先一致性备份数据，再运行修复后的中心；启动时自动事务迁移至 v6，同时兼容已经含有该字段的 v4/v5 数据库。源码开发模式 `tsx watch` 保存修改后会自动重载并执行迁移；生产源码运行须先重新构建 API。无需重建节点、删库或更换 Agent，原失败批次会自动重试。v6 不能直接用旧中心程序打开；回退须同时恢复升级前程序与一致性数据库备份。

所有新采集默认关闭。节点详情进入“系统诊断”或“容器与进程”开启，中心配置版本与 Agent 应用版本分别显示，保存失败继续使用旧配置。与探测共用扩展配置版本，但下发时按各 Agent 声明的能力投影，旧 Agent 不会收到新配置字段。基础流量配置不变。

## 系统诊断

- CPU user/system/iowait/steal、归一化负载、Swap 换入换出、CPU/内存/I/O PSI、设备 IOPS 与平均等待：5 秒。
- TCP 连接状态和重传速率、网卡包/错误/丢弃速率：15 秒。
- 文件系统容量与 inode、服务运行状态：30 秒。挂载点与块设备 I/O 分开；文件系统身份包含设备号、类型和内核 fsid。
- 每个对象带独立采样时间；新鲜窗口为 `max(15 秒, 3 × 周期)`。首次、重启、计数器重置、采样间断返回空；无 I/O 时 IOPS=0、等待时间为空。不支持、权限不足、无 Swap 和零使用有不同表达。
- 服务只查询白名单：systemd 使用固定 `systemctl show --property=ActiveState --value -- NAME`，OpenRC 使用固定 `rc-service NAME status`。不执行 shell、自定义命令、重启或修复动作。权限不足保留非 root 身份并显示不可读。
- 告警中心可建立 iowait/steal/PSI/inode/IOPS/服务及进程停止规则。对象名称直接复制诊断页选择器中的值，事件可跳转历史。停止规则的值为 0（运行）或 1（停止），建议触发/恢复阈值均设 0.5。仅对应指标的新样本推进持续时间，节点心跳不作为指标恢复证据。

容量写满估算要求至少 3 个连续完整 UTC 日、每天有效观测 ≥95%，最长使用最近 7 天同一文件系统数据。扩容、更换文件系统、日间使用量下降超过 5% 或当前采样陈旧后隐藏估算，重新建立趋势。它是基于中心已收到记录的线性估算，未收齐历史时不承诺预测准确。

## 容器及进程

进程采用精确名称白名单，最多 20 个名称，每 30 秒查询。每个名称都有运行状态，匹配进程按 RSS 排序，仅保存前 10 个；身份包含 boot ID、PID 和创建时间。不保存命令行、环境变量或文件内容，退出记录继续留在历史。CPU 以单核 100% 计，多核进程可超过 100%。

Docker 默认关闭，需要在 Agent **本地** 0600 配置中加入 `docker_proxy_url`，例如 `http://127.0.0.1:2375`。该地址只能是字面量 loopback IP，不能从中心设置为任意地址。请先部署带路径及方法 ACL 的受限代理，仅允许以下 GET 请求：

```text
/containers/json?all=1
/containers/{64 位容器 ID}/json
/containers/{64 位容器 ID}/stats?stream=false
```

代理本身如何保护 Docker socket 由实际部署决定；只读挂载 socket 并不限制 Docker API 方法。Agent 不直接挂载 socket，也不发 POST/exec/启动/停止请求；禁用环境代理、重定向，限制响应大小与超时。每次最多 10 个容器；名称用于展示、完整 ID 用于身份。采集运行/健康/重启次数、CPU、内存及累计网络/I/O 字节，非运行容器的 CPU/内存不填零。CPU 也以单核 100% 为基准。

## 资产与通知

节点“资产”页维护供应商、地区、IP、备注、价格最小单位整数、ISO 币种、账期、到期时间、带宽及提醒渠道。到期前 30/7/1 天按节点、资产版本、阈值去重；跨档只产生当前最高档事件。修改配置关闭旧通知，保存后立即重算。价格汇总按币种分别列出录入金额，未做汇率换算或月费归一化。

通知复用持久 outbox、渠道加密、维护窗口与节点启用状态。未选渠道仍记录事件。提醒不执行自动续费。

## 批量接入

“运行管理”创建注册凭据：有效 5 分钟～24 小时、最多 1～50 台、可撤销。只保存摘要，令牌仅创建时显示一次。通过 Authorization 头提交注册；不把令牌放入 URL 或命令行。相同注册 ID + request ID 在凭据有效且未撤销时重试返回同一节点和凭据，不重复消耗次数。

从中心下载并检查 `install-agent.py`，或使用项目中的 `scripts/install-agent.py`。默认按目标架构从同一中心下载 Agent 与 SHA256SUMS，不需要访问 GitHub；下面为占位示例，替换中心地址和注册 ID：

```bash
curl --fail --show-error --proto '=https' https://monitor.example.com/downloads/agent/install-agent.py -o install-agent.py
python3 install-agent.py \
  --server https://monitor.example.com \
  --registration-id 11111111-1111-4111-8111-111111111111
```

默认只预览。正式安装增加 `--apply`，令牌通过 getpass 隐藏输入。工具识别 amd64/arm64 与 systemd/OpenRC、先校验下载，再注册，创建非 root `trafficagent` 账号和固定服务单元。已有配置、数据、二进制或服务单元时拒绝覆盖，现有节点升级仍使用原运维流程。

可添加 `--sha256 <对应架构的SHA256>` 固定已核对的校验值。使用其他发布源时，继续支持 `--download-url 'https://github.com/x-dr/linux-traffic-monitor/releases/download/vX.Y.Z/traffic-agent-linux-{arch}' --sha256 <对应架构的SHA256>`；自定义地址不能省略校验值。下载不发送注册凭据，仅允许 HTTPS；清单与程序来自同一中心时，SHA256 用于传输完整性校验，仍需信任中心。预览不会联网，也不会创建文件或请求注册。

本工具保留不含令牌的注册尝试信息在 `/var/lib/trafficmon-installer/attempt.json`；同一次安装中断可加 `--resume --apply` 重试。仅接续同中心、注册 ID、校验值的安装，并校验已有二进制、配置和固定单元，不替换其他安装。若注册凭据已经失效且尚未保存节点配置，需管理员核对中心已注册节点后处理，不能自动抹掉节点或重建已有数据目录。

## 长期历史与报表

资源、磁盘 I/O、系统诊断和工作负载原始分钟保留 30 天；小时汇总保留 366 天，天汇总 3×366 天。原始记录清理只处理已提交汇总且没有脏桶的完整小时。迟到更新标记对应小时，事务重算小时及其自然 UTC 日。平均值按有效次数/观测时间加权，最大值、有效次数及观测秒数分别保留，不能把缺口补零。流量原始分钟和累计继续长期保留。

节点“长期历史”查看原 CPU/内存、磁盘汇总；诊断页直接切换 30 天/1 年/3 年。历史每页最多 2000 桶，可选择对象和较粗粒度；原始探测仍保留 7 天，长期报表不伪造已到期的 P95 或可用率。

“运行管理”配置日、周（周一开始）、日历月或节点计费周期报表，支持节点集合与分组交集、IANA 时区、启用及通知渠道。30 秒扫描一次；停机恢复只生成最近一个完整周期，相同任务版本/周期唯一，超过边界 5 分钟生成标记迟发。计费周期使用节点现有时区与月起始配置，流量仍按分钟边界与 BigInt 精确汇总。

报表中的可用率是近 7 天**有效探测的观测成功率**，不是整段时间的在线率；历史不完整时为空。故障时长是离线告警区间的并集，未配置离线规则时为空。资源“已观测秒数”按有效 CPU 样本×5 秒计算并限于周期长度；不能据此推断没有覆盖的时段健康。容量列来自该周期最后收到的根挂载点样本。

CSV 沿用管理员会话，单次至多 50 节点，列表每页 20 期，任务最多 50 项；导出防公式注入。任务停用或版本改变会取消尚未发送的旧报告通知。

## 备份、恢复与监控自身

升级前停止相应写入或使用 SQLite 一致性备份，分别保留旧中心镜像、Agent 二进制、两个库、配置及独立通知密钥。新程序发现高版本库时拒绝打开；回退必须恢复匹配程序与库，不仅替换二进制。不要将 Agent 与中心数据库混用。

`scripts/agent-resync.py` 已支持 v2/v3/v4。仅用于中心恢复旧备份后，停止仍完整的 Agent、预览指定时间范围，再显式确认并备份；给诊断/工作负载记录分配高于序列与 ACK 水位的新 revision，同时修改 JSON 内 revision，保留 source_id、累计、原计数器基线及各流游标。超过原始保留期的新指标无法重建，资源汇总也只能来自现存原始记录或备份。

诊断页显示每流积压、最早时间、确认水位、上次成功 ACK，以及探测/诊断/工作负载未确认过期丢弃摘要。旧资源/磁盘流未提供丢弃统计时明确显示未提供，不将未知填成 0。运行管理显示数据库页大小、最近/最大上报耗时、最近一次判定调度延迟、通知队列和汇总积压。这里的耗时为进程内统计，不代表公网延迟或 P95。

本地测试不替代真实 VPS、特权差异、长期 systemd/OpenRC 常驻、受限 Docker 代理、公网通知或 arm64 设备运行。正式发布检查见 [进度](monitoring-upgrade-progress.md) 和 [验证记录](verification.md)。
