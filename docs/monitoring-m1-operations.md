# 告警与流量套餐使用及升级

日期：2026-11-02。范围为 M1-A / M1-B；[实际进度](monitoring-upgrade-progress.md)、[设计](monitoring-m1-design.md)、[验证结果](verification.md)。本地实现不表示默认发布镜像已经包含这些改动；部署须使用包含本次源码的镜像。

## 版本与升级

中心 SQLite 从 `user_version=2` 增量升级至 `3`，Agent 仍为 v2，沿用 Go Agent 1.1.0 和 v1 协议，首批无需重新安装 Agent。新增模块默认关闭，不创建规则、套餐或真实通知渠道。

生产升级前保存镜像摘要、部署配置，并用 SQLite `.backup`、SQLite Backup API 或停止服务后完整保存数据库与 WAL 的方式备份；不要仅复制运行中的主数据库文件。先在数据库副本验证升级。中心迁移失败时停止启动并保留原数据，不重新初始化。通知密钥单独安全备份，不与数据库放在同一备份包。

先更新中心，再检查原 Agent 上报、SSE、原配置确认、历史、累计流量；然后在页面手动创建规则与套餐。旧版中心会拒绝 v3 数据库，回退必须停止新服务并恢复匹配的旧程序、数据库和配置备份。仅更换镜像不能完成回退。

## 通知密钥与外发配置

直接运行中心时设置 `NOTIFICATION_KEY_FILE`，文件内容为 32 个原始字节或 64 位十六进制，生产使用持久文件。密钥未配置时监控仍启动，渠道保存被禁用；密钥错误时无法解密已有渠道，不会返回原文。

例如在部署主机新建独立密钥文件（仅首次创建；**已有文件不得覆盖**）：

```bash
test ! -e /安全目录/notification.key
(umask 077; set -C; openssl rand -hex 32 > /安全目录/notification.key)
```

Compose 的中心使用 uid/gid 1000；宿主机密钥需对容器内该账户可读，例如将单个文件所有者设置为 `1000:1000` 并使用 `0400` 权限，避免其他账户读取。自行更改容器用户时使用实际 uid。密钥不进入 Git、请求参数、日志或页面。

可选的 [通知 Compose 覆盖文件](../deploy/compose.notifications.yaml) 单独挂载密钥。先在部署环境设置 `NOTIFICATION_KEY_PATH` 为绝对文件路径，然后检查：

```bash
docker compose -f compose.yaml -f deploy/compose.notifications.yaml config --quiet
```

实际部署时相同的两个 `-f` 参数都要保留。默认 `compose.yaml` 无须密钥即可继续运行监控。上述覆盖文件不自动启动服务。

| 配置 | 默认与用途 |
| --- | --- |
| `NOTIFICATION_KEY_FILE` | 未设置；AES-256-GCM 加密渠道地址和 Authorization |
| `WEBHOOK_ALLOWED_HOSTS` | 空；逗号分隔的精确主机名，显式允许该主机解析到私网 |
| `WEBHOOK_ALLOWED_CIDRS` | 空；逗号分隔的允许私网 IPv4/IPv6 网段 |
| `WEBHOOK_ALLOW_HTTP` | `false`；只有明确设为 `true` 才允许 HTTP，适用于隔离测试或明确的内网集成 |

默认 HTTPS、校验证书、不跟随重定向，禁止 URL 用户信息与片段；云元数据、链路本地、多播和未指定地址即使列入私网允许名单也拒绝。保存时和发送时分别解析地址，连接固定到已校验 IP，避免解析变化绕过私网限制。不要将宽泛网段加入允许名单。

在“系统设置 → 通知渠道”保存 Webhook，鉴权头可选。读取只返回脱敏主机、是否设置鉴权。编辑时秘密留空代表保留，“清除现有鉴权头”显式清空。测试通知每 IP 每分钟最多 3 次；手动重试每分钟最多 6 次，只重试失败消息。

通知 JSON 包含事件 ID、阶段、节点、规则名称、级别、触发/恢复时间、当前值、阈值和详情链接；HTTP `Idempotency-Key` 为稳定幂等键。2xx 视为成功；网络错误、408、429、5xx 最多 5 次尝试，基础重试间隔为 30/120/600/1800 秒，429 的等待上限为 1800 秒。其他非 2xx 状态终止自动投递。远端接收后本地记账失败仍可能重试，接收端应使用幂等键去重。

## 告警与维护

告警中心支持 CPU、内存、磁盘使用率、磁盘剩余字节、节点离线、数据陈旧、带宽使用率；带宽必须填写 Mbps 容量，计算按 `B/s × 8 / (Mbps × 10^6)`。规则支持全部启用节点、指定节点集、分组和标签，页面显示匹配预览。

模板默认关闭。离线/陈旧模板等待 120 秒；列表仍按 15 秒陈旧、45 秒离线展示。CPU/内存等默认持续 5 分钟、恢复持续 2 分钟；阈值可调。除磁盘剩余空间外，异常为严格超过触发阈值，恢复为严格低于恢复阈值；剩余空间方向相反。离线/陈旧恢复需要新鲜连接/样本；恢复阈值为允许的最大数据年龄（1～15 秒，默认 15 秒），持续时间由 `recovery_seconds` 控制。

中心每 5 秒独立判定，不依赖浏览器；资源超过 15 秒无有效新样本、时钟超前或采集错误时标为未知，未触发规则重新计时，已触发事件保持未恢复。中心重启保留活跃事件与 outbox，停止期间不算连续有效采样。确认仅记录人工处理，静默 1 小时只暂停通知。

维护窗口输入含时区的 ISO 时间，内部保存 UTC，事件按浏览器本地时区显示。维护中照常记录事件，结束时只发送仍存在异常的摘要，期间恢复的异常不补发。节点停用/归档、规则归档或配置变更会关闭相关事件、取消待发送消息，并记录配置关闭原因。

事件与节点时间线保留 180 天，投递明细保留 30 天；活跃事件、未完成消息及去重状态不会按明细保留时间删除。终止事件仍可在历史中查看。

## 套餐、重算与预测

节点详情“流量套餐”独立保存 GB/TB（十进制）或 GiB/TiB（二进制）额度、计费方向、固定网卡、提醒阈值和渠道；先预览再保存，预览过期会要求重新计算。更改周期前显示套餐计费前后预览；修改采集网卡会提示检查独立计费网卡。

四种方向为 RX、TX、RX+TX、`max(周期 RX, 周期 TX)`，先汇总所选网卡再应用公式，不能逐分钟取最大值。BigInt 汇总与阈值比较；字节在 JSON 中以十进制字符串表示。原节点与全局累计口径不变。

默认 80/90/100% 提醒；同周期、策略版本、阈值去重，跨档只发送当前最高档。修改套餐或计费周期递增策略版本，最多重算提醒一次。过去周期补传只修正记录，不触发过期提醒。

预测取最近 7 个已结束的节点本地自然日，至少 3 天，每个计费网卡分钟记录覆盖率均不低于 95%；按真实日时长加权，支持夏令时。RX、TX 分别预测后应用公式，`max` 耗尽取两个方向最早达到额度的时刻。有效速率为零时不显示耗尽时间，采样异常或历史不足时隐藏预测。

所有数值基于中心已收到的分钟记录，不证明全部补传完成或连续采样，不等同于服务商账单。首版不自动限速或停机。

## 中心回退后重新同步

[独立维护工具](../scripts/agent-resync.py) 使用 Python 3 标准库，兼容现有 v2 Agent 数据库，不要求替换常驻 Agent。它用于**中心恢复旧备份而 Agent 本地库完整**的情况；不支持直接恢复更旧的 Agent 库。旧 Agent 库的计数器基线、累计量和历史高水位无法核实时，应暂停恢复并保留现场。

先停止对应 Agent，保存当前完整本地数据库，然后预览缺失时间范围 `[from,to)`；时间必须含时区并对齐整分钟：

```bash
python3 scripts/agent-resync.py --db /Agent数据目录/traffic.db \
  --from 2026-11-01T00:00:00+08:00 --to 2026-11-02T00:00:00+08:00
```

核对范围、行数与序列高水位后正式执行，备份路径必须不存在：

```bash
python3 scripts/agent-resync.py --db /Agent数据目录/traffic.db \
  --from 2026-11-01T00:00:00+08:00 --to 2026-11-02T00:00:00+08:00 \
  --apply --agent-stopped --backup /独立备份目录/before-resync.db
```

工具先 `VACUUM INTO` 一致性备份，再在事务中为范围内流量、资源、磁盘记录与当前 totals 分配高于全部现存 revision、游标和 sequence 的新 revision；已知更高的历史水位可用 `--revision-floor` 明确传入。source_id、原分钟数值、累计量、网卡/磁盘基线和现有游标保持不变。新 revision 会被原 Agent 自动补传，不会因确认游标领先而跳过。

重启 Agent 后检查中心历史及累计量；重复补传按 revision 覆盖，不叠加。工具不停止服务、不安装程序、不清空数据库、不改变凭据，也不能重建已超过保留期限的资源数据、仅存中心的新规则或通知记录。

## 本地验收依赖

`npm test` 的恢复演练调用 Python 3，TLS 用例调用 OpenSSL 创建临时自签名证书；运行测试前需安装二者。它们不是中心生产服务的运行依赖。浏览器验收另需 Chrome/Chromium、已构建 Web 和 amd64 Agent，使用临时端口 18766/18767。
