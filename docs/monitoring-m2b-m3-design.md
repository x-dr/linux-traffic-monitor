# M2-B / M3 实施设计

日期：2026-11-02。范围：完成剩余本地功能；不发布、不部署、不操作用户数据库。

## 实施顺序

1. M2-B：增加 diagnostics:1 能力、独立分钟历史/ACK、CPU/PSI/文件系统/IOPS/TCP/服务与同步诊断。
2. M3 采集：增加 workloads:1 能力，按白名单采集进程；通过本机受限 Docker API 代理只读采集容器。
3. M3 管理：资产资料与 30/7/1 天通知、短期批量注册及校验安装工具。
4. M3 历史：资源/磁盘与新指标小时、天汇总，迟到更新重算，提交汇总后清理原始记录。
5. M3 报表：日/周/月和计费周期报表、时区定时任务、最近一期补发、限量 CSV。
6. 完整回归、迁移与恢复验证，更新进度及实际边界。

## 数据与兼容

中心 v4→v5，Agent v3→v4，事务迁移保留原 source_id、凭据、基础采集与同步游标。扩展配置新增可选 diagnostics/workloads；只下发 Agent 声明支持的配置。新 Agent 先基础协商，旧中心回退剥离全部扩展；每流精确 ACK，不互相推进。

新指标按对象与身份保存分钟统计（最后值、有效样本数、均值、最大值、观测时长），对象各自带采样时间与周期。容量对象身份来自文件系统设备号及挂载信息；磁盘、CPU、网络计数器首样/重置/中断返回空。缺失、不支持、权限不足分别标识。诊断及工作负载独立 worker，不阻塞基础网络采样。

小时保留 1 年，天保留 3 年；原始 30 天。流量原始分钟长期保存。汇总桶按 UTC 存储，仅用于资源展示；计费周期仍查询原始流量。长期网络分位数不以平均 P95 伪造，原始探测到期后不提供 P95。

## 页面与交互

布局草图见 monitoring-m2b-m3-layout.svg。节点新增“系统诊断”“容器与进程”“资产”页签；系统设置增加中心诊断、批量注册和报表入口。诊断支持对象/指标/时间窗口筛选，保存在 URL；显示独立新鲜度、能力、采样缺口与同步水位。历史不补零。资产和配置保存后显示确认状态；刷新不覆盖未保存输入。手机使用卡片与纵向表单，320px 可操作；深浅主题沿用现有 token。

## 安全边界

服务仅允许固定 systemd/OpenRC 状态查询，无自定义命令。进程不采集命令行/环境；容器 API 地址由 Agent 本地配置且只允许 loopback，固定 GET 路径，禁止代理和重定向。注册令牌只存摘要；管理员创建时显示一次，注册通过 Authorization 请求头，过期/次数/撤销在事务内检查。安装工具交互读取令牌、校验 SHA256、识别架构/init，已有安装默认拒绝，不覆盖数据。所有管理 API 复用 Cookie/CSRF；CSV 处理公式注入与输出上限。
